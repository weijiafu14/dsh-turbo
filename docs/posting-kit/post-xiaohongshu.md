**配图顺序**：`assets/seed-maze.png`（种子图）→ `assets/01-dungeon-crawler.png`（第一人称迷宫）→ `assets/02-maze-strike.png`（CS 版开场）→ `assets/03-cs-hud.png`（战斗 HUD）

---

斯坦福 Scaling Intelligence Lab 前段时间发了个 LLM-as-a-Verifier：同一个问题让开源模型跑 5 遍，再用同一个模型当"验证者"把 5 份答案排序、挑最好的一份交出去。他们的论文数据是 Terminal-Bench 从 79% 提到 88%，成本还只有闭源前沿模型的零头。

我把这套东西做成了 DeepSeek Harness 的插件 dsh-turbo，装完在模型列表里选一下就生效，不用改任何工作流。

**装法就两步**

```
dsh plugin add dsh-turbo
export DEEPSEEK_API_KEY=sk-...
```

第二步大概率你已经配过了——它读的就是官方 DeepSeek 路由那个 key。重启后在模型选择器里选 DeepSeek Turbo，完事。

**它到底做了什么**

不是简单的"跑几遍让 AI 挑一个"。论文里三个关键设计我都实现了：

· 验证者给 1-20 分，但**不取它说出口的那个数字**，而是读 score token 的概率分布算期望值——论文的消融实验说，带 logprob 的一次评分 ≈ 普通裁判投 16 次票
· 评分拆成三个维度分别打（是否满足要求 / 输出是否对得上 / 有没有错误信号），再平均
· 选最优用"概率枢纽锦标赛"：先随机环形两两比一轮消除位置偏见，选出种子选手当枢纽，其余的跟枢纽比，最后用 Bradley-Terry 概率累积胜场

**实测：一张图 → 一个能玩的 3D 游戏**

我把一张迷宫图粘进对话框，提示词里**一个"迷宫"字都没有**，让它做第一人称 3D 游戏。

它第一句回的是：「IMAGE SHOWS: 一个矩形正交迷宫，蓝色墙体、深色背景，左上角绿色圆点是起点，右下角红色菱形是终点」——全靠看图。

然后写出 26KB 的 three.js 游戏：指针锁定第一人称、程序生成石墙纹理、走廊火把点光源、雾效、8 个可收集的发光球、右上角实时小地图、到达终点有胜利画面。

接着我让它改成 CS，它在新文件里写了 56KB：AK47 视图模型带后坐力、射线命中、墙上弹孔、30 发弹匣和换弹动画、6 个会巡逻和视线追击的敌人 AI、击杀提示流、雷达、回合倒计时、记分板。

**两个游戏的代码我一行没改过**，全是模型自己写的。它甚至自己写了两个 smoke 测试脚本去验证自己的代码，最后还自己用 md5 检查了一遍有没有误改我说过不许动的原文件。

**背后跑了多少**

两轮加起来 25 次 fan-out，每次 5 个候选，**零降级**，740 次验证调用，1900 万 token 走了缓存命中。缓存这块是我特意优化的：验证提示词做了分层，同一对候选在三个评分维度之间字节完全一致，所以候选代码（经常是整个几万 token 的文件）只按缓存价算一次。

**说点实在的**

论文那个 79%→88% 是**他们的数据**，在他们的测试台上测的。我自己还没做同题 A/B 对照，所以质量提升这件事我只能说"论文这么说"，不能替它背书。另外这东西天然更慢——一次回答要等 5 个候选全部生成完再验证完，图快的场景不适合。
